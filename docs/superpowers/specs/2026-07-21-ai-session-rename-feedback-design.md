# AI 会话重命名提示词与命名状态设计

日期：2026-07-21

## 背景与问题

工作台会话树提供“AI 重命名”操作，但当前流程存在两个相互放大的问题：

1. 标题生成请求把原始用户 prompt 直接作为普通 `user` 消息发给 Haiku。即使 system prompt 要求生成标题，模型仍可能把原文识别为待执行任务，返回“需要先了解代码结构”一类问询或执行式回复，并被现有清洗逻辑截断后写成会话标题。
2. 点击“AI 重命名”后，只有仍然打开的菜单项会显示 spinner。菜单关闭后，会话行本身没有持续状态，用户看不出请求是否已开始、正在处理哪条会话，也无法区分网络等待和点击无效。

本设计同时修正标题生成契约和会话行反馈，避免只遮盖错误标题或只增加动画而保留错误请求结构。

## 目标

- 把原始用户 prompt 明确包装为“仅供概括的标题素材”，避免模型执行其中的任务。
- 生成结果必须是单行、短小、名词短语化的标题，不包含确认、承诺、问询或解释。
- 手动 AI 重命名开始后，目标会话标题区域立即显示明确的原位加载反馈。
- 命名成功后原位显示新标题并保留现有成功 toast；失败后恢复旧标题并显示现有错误 toast。
- 命名期间阻止重复触发，并让其他会话的 AI 重命名入口明确处于不可用状态。
- 中文、英文和繁体中文界面均有对应的“AI 正在命名”文案。
- 动画不引发会话行高度、宽度或列表排序抖动，并尊重减少动态效果的系统偏好。

## 非目标

- 不更换标题生成模型、API 提供商或持久化后端。
- 不改变自动话题命名的启用开关和会话创建时机。
- 不改变普通手动重命名输入框的交互。
- 不允许同时对多条会话执行 AI 重命名；本次继续使用单请求状态。
- 不重构整个工作台侧栏或会话列表虚拟化、拖拽与排序逻辑。
- 不修改工作区内另一个尚未提交的 Claude 1M 模型状态修复。

## 根因与方案选择

### 提示词根因

旧请求结构为：

- system：要求生成短标题；
- user：未经包装的完整原始 prompt。

这使原始命令与标题生成指令处于不同角色层级。模型可能优先延续 user 消息里的任务意图，产生助手式问询、承诺或步骤，而非标题。

### 采用：标题生成契约 + 输出防线

请求改为两层约束：

1. system prompt 声明模型是“会话标题生成器”，唯一职责是概括，不执行、回答、规划或继续原始任务。
2. user prompt 把原文放入 `<PROMPT>...</PROMPT>` 素材边界，并再次说明边界内文本不是待执行指令，命令句应改写为名词短语。

输出继续经过清洗与长度限制，并新增对助手确认前缀的剥离。测试直接断言请求消息不再等于原始 prompt，防止未来回归为裸消息。

### 采用：A｜标题原位反馈

用户选定 A 方案。AI 重命名期间，原有标题临时替换为：

`旋转星芒 icon + AI 正在命名… + 文字流光`

状态直接显示在目标会话行的标题位置。会话行尺寸保持不变，旧标题不被持久化覆盖；请求完成后清除 busy 状态，成功时显示已更新标题，失败时自然恢复旧标题。

### 未采用：旧标题 + 右侧状态徽章

能够保留旧标题，但工作台侧栏最窄为 200px，状态徽章会与标题、操作菜单和草稿徽章竞争横向空间，造成更严重的截断。

### 未采用：纯骨架动画

视觉更克制，但缺少明确语义，容易被理解为列表渲染未完成或数据加载异常，不能解决“点击是否生效”的核心疑问。

## 组件设计

### `sessionAutoTitle`

`generateSessionTitleFromPrompt` 统一构造标题专用请求：

- system prompt 明确唯一职责与禁止行为；
- user prompt 使用素材边界包装原始 prompt；
- `avoidTitle` 继续加入 system prompt，手动 AI 重命名时避免原样返回当前标题；
- Haiku 的模型、token 上限、温度、超时和重试策略保持不变。

`sanitizeGeneratedSessionTitle` 在原有单行、去编号、去引号、去“标题：”和长度限制基础上，剥离常见助手确认前缀，例如“好的”“可以”“我来帮你”“已为你生成标题”。清洗只作为第二道防线，核心修复仍是请求结构。

如果 Haiku 请求失败、超时或返回空内容，保留现有本地首行 fallback。手动 AI 重命名若生成标题与当前标题相同，继续重试并在无新标题时返回 `null`，避免伪成功。

### `WorkbenchSidebar`

继续由顶层 `aiRenamingSessionId` 保存当前正在命名的会话 ID，避免把异步请求状态分散到每个会话行。

请求生命周期：

1. 触发时先检查是否已有命名请求；空闲时立即写入目标 ID。
2. 菜单关闭后，目标会话行通过 `aiRenamingSessionId === session.id` 得到 `isAIRenaming`。
3. `finally` 清除 ID，确保成功、空内容、API 异常或持久化异常都会退出 loading。
4. 任意请求进行中时，其他会话的 AI 重命名菜单项也禁用，避免点击后无反馈。

### 会话行标题区域

会话行区分三种互斥显示：

1. 普通手动重命名输入框；
2. AI 命名中的原位状态；
3. 普通标题。

普通手动重命名输入框优先级最高；AI 命名开始前不会同时进入普通重命名状态。AI 命名状态包含：

- 固定大小的 `Wand2` 星芒图标，使用旋转动画；
- `workbench.ctx.aiRenaming` 本地化文案；
- 专用文字流光 class，只改变文字绘制，不改变布局尺寸；
- `aria-live="polite"` 与 `aria-busy="true"`，让辅助技术获知状态。

在 `prefers-reduced-motion: reduce` 下停止旋转和流光，保留图标与文案，状态仍然清晰。

成功后清除命名状态，现有 `sessionTitles` 更新触发新标题渲染；新标题使用短淡入动画。失败时 `sessionTitles` 未发生修改，清除命名状态即可恢复旧标题。

## 数据流

1. 用户从目标会话菜单点击“AI 重命名”。
2. `WorkbenchSidebar.aiRenameSession` 设置 `aiRenamingSessionId`。
3. 会话树重新渲染，目标行把普通标题替换为“AI 正在命名”动画；全部 AI 重命名入口进入不可重复触发状态。
4. 调用方优先使用 `session.first_message`，占位或缺失时读取历史中的首条用户消息。
5. `renameSessionWithAI` 调用标题生成器；原始 prompt 以素材边界发送给 Haiku。
6. 标题经过清洗、当前标题差异检查和持久化重试。
7. 成功时更新 `sessionTitles`、对应 tab 标题并显示成功 toast。
8. 失败、空内容或无新标题时显示错误 toast。
9. `finally` 清除 `aiRenamingSessionId`，会话行恢复普通标题状态。

## 错误、并发与状态一致性

- `aiRenamingSessionId` 非空时不启动第二个请求。
- 菜单项的 disabled 规则与处理函数 guard 使用同一状态，避免界面显示可点但回调静默退出。
- prompt 缺失时仍经过 `finally` 清理 loading，并显示“无可用会话内容”提示。
- 请求失败或持久化失败时不提前修改 `sessionTitles`，旧标题不会丢失。
- 标题持久化成功后继续派发 `session-title-changed`，现有会话列表、tab 和搜索标题同步机制保持不变。
- 自动话题命名与手动 AI 重命名共享标题生成契约；手动流程继续绕过“已有标题就跳过”的自动命名限制。

## 国际化与文案

新增键：`workbench.ctx.aiRenaming`。

- 简体中文：`AI 正在命名…`
- English：`AI is naming…`
- 繁体中文：`AI 正在命名…`

现有 `aiRenamed`、`aiRenameFailed` 和 `aiRenameNoContent` 文案保持不变。

## 测试设计

### 标题生成单元测试

- 断言原始 prompt 被 `<PROMPT>` 边界包装，消息内容不等于原始 prompt。
- 断言 system prompt 包含“唯一任务”和不执行原始 prompt 的约束。
- 断言问询式/确认式助手前缀不会成为最终标题。
- 保持标题长度、Haiku 重试、超时 fallback、持久化重试、去重和当前标题差异测试通过。

### 工作台集成安全测试

- 断言会话树接收并计算目标行 `isAIRenaming`。
- 断言目标行标题区域包含 `Wand2`、旋转/流光状态和 `aiRenaming` 文案。
- 断言命名状态带有 `aria-live` 和 `aria-busy`。
- 断言任意 AI 命名进行中时菜单入口禁用。
- 断言现有 `finally` 清理和成功/失败 toast 路径仍存在。
- 断言三种语言均包含新增键。

### 回归验证

- 运行标题生成和工作台相关 Vitest 测试。
- 运行 TypeScript typecheck。
- 运行生产构建。
- 在本地界面触发 AI 重命名，观察菜单关闭后的会话行 loading、成功标题替换和失败恢复。

## 验收标准

- 点击“AI 重命名”后，无需保持菜单打开，目标会话行立即显示旋转星芒和“AI 正在命名…”流光文案。
- 命名期间会话行高度、项目树顺序和相邻会话位置不跳动。
- 同一时间只有一个 AI 重命名请求，其他入口显示为不可用。
- 类似“我需要先了解你现有的代码结构”或“好的，我来帮你”不再被保存为标题。
- 成功后目标会话行和对应 tab 显示新标题，并出现成功 toast。
- 失败、无内容或未得到不同标题时恢复旧标题，并出现对应错误 toast。
- 简体中文、英文和繁体中文界面均显示正确命名状态。
- 定向测试、类型检查和生产构建全部通过。
